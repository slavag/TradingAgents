# US Momentum Discovery Watchlist

## Purpose and boundaries

Upgrade the existing **Discover** tab into a research shortlist of up to 20 US-listed stocks worth investigating for current momentum. The list is not a Buy/Sell recommendation, a price target, or a substitute for a TradingAgents analysis. A candidate's presence means that dated price and liquidity checks passed after at least one mover or attention feed nominated it, not that its expected return is positive. Opening Discover or refreshing it must never start an analysis job or call an LLM.

The user chose a trend/momentum-first screen, US-listed securities for the first version, and the existing Discover tab rather than a second navigation item. Tickers absent from My Research appear first; previously analyzed tickers remain visible with a badge. Within each group, the same market-signal ranking applies. Default to 20 candidates and allow 15. Never pad a short result with unqualified symbols.

The primary checkout currently contains unrelated, uncommitted AMD report changes. Preserve them. Do not commit, push, run paid models, or call live data-provider endpoints for QA without separate authorization.

## Data sources and eligibility

Use fixed, server-owned source adapters, not caller-supplied URLs. Build the candidate pool from the existing in-repository [ApeWisdom](https://apewisdom.io/api/) and StockTwits activity parsers, [Alpha Vantage's US top gainers and most-active endpoint](https://www.alphavantage.co/documentation/), and optional [FMP biggest gainers](https://site.financialmodelingprep.com/developer/docs/stable/biggest-gainers) and [most-active](https://site.financialmodelingprep.com/developer/docs/stable/most-active) endpoints when the configured account permits them. **Either a movers feed or an attention feed can nominate a symbol**; appearing in both improves its rank but is not required for eligibility after identity, momentum, and liquidity verification. This keeps a partial feed outage from automatically emptying the list. Do not require FMP entitlement for the feature to work. The new path must not depend on the current hard-coded MyAgent script outside this repository. Existing `/api/speaking-stocks` callers can remain compatible while Discover adopts the new endpoint.

Normalize and deduplicate symbols before any market fetch. Limit source rows, candidate symbols, response sizes, timeouts, and concurrent identity lookups. Use the existing market-data stack to obtain completed daily price and volume history in bounded batches: split-adjusted closes for returns, and unadjusted close times actual volume for dollar-liquidity checks. Verify that a displayed item is an active US-listed equity, not an ETF, fund, OTC symbol, or delisted quote, using available provider identity metadata; omit identity-unknown items from the qualified list rather than calling them stocks. Require at least 50 usable sessions, a latest close of at least 5 USD, 20-session average dollar volume of at least 10 million USD, a positive five-session return, and a quote no older than two US trading sessions. Missing prices, currency, volume, or dates do not count as zero or as passing evidence. If these rules yield fewer than 15 candidates, show the smaller count and why.

## Ranking and explanation

Rank only eligible equities. Use a deterministic, bounded research-priority score composed of five-session return, 20-session return, close-versus-20-day and 20-day-versus-50-day trend checks, relative volume versus the prior 20 sessions, and independent source corroboration. Cap each numeric contribution so a single extreme return cannot dominate; mark a one-day move above 25% as a high-volatility spike and apply a small ranking penalty rather than silently excluding it. Document the exact point bins and tie-breakers in code and tests before release. This score is an ordering heuristic, never a probability or investment confidence score.

For every candidate, return the measured values, the completed quote date and price basis, source names, a short explanation derived from those values, and any risk flag. Distinguish an attention mention from verified market momentum. Do not invent a company catalyst or claim that a price move will continue. The backend obtains the local saved-research index to mark `already_analyzed`; that history is never sent to upstream data providers. Sort new-to-you candidates first, then analyzed candidates, using score and symbol as stable tie-breakers within each group.

## API, freshness, and failure behavior

Add one local-only, read-only endpoint such as `GET /api/discover/stocks?limit=20`, with `limit` restricted to 15 or 20 and a separate explicit refresh flag. The response contains a bounded status (`fresh`, `cached`, `partial`, `stale`, or `unavailable`), UTC retrieval time, quote-as-of date, up to the requested number of items, provider availability flags, and safe warning codes. It never returns credentials, raw provider response bodies, arbitrary remote URLs, or local history records. Browser rendering converts UTC times to the user's locale and labels delayed/end-of-day data accurately.

Cache the source/price screen in memory for roughly 30 minutes, coalesce concurrent requests, and apply a short manual-refresh cooldown to protect provider quotas. Opening the Discover view may load its cached or first snapshot but app startup and unrelated analysis flows do not prefetch it. A failed refresh may retain the last good in-process snapshot only with an explicit **stale** label and its original timestamp. A missing key, entitlement failure, timeout, malformed payload, or partial outage must not crash the tab; omit the failed source and show a concise warning. If no trustworthy snapshot remains, show an actionable empty/error state rather than stale candidates as current. Keep all hosted requests on fixed HTTPS endpoints and enforce the app's local/same-origin access boundary.

## Discover interface

Keep the current market overview. Replace “Chatter Candidates” with a “Momentum watchlist” area containing a 15/20 count control, manual Refresh, last-updated and quote-as-of labels, and a persistent note that these are research candidates, not trade recommendations. Show **New to your research** first and **Previously analyzed** second. Each accessible card presents ticker, verified company name when available, completed close and quote currency, five-session and optional 20-session move, relative-volume/trend checks, source badges, a complete “Why check it” sentence, and any spike/stale warning. Avoid opaque technical scores as the sole explanation.

Reuse the existing ticker-details and **Add to analysis** flow, but make the action visible on each card. Adding a ticker only fills the New Analysis form; it does not submit it. Previously analyzed cards also link to the saved My Research detail. Keep loading, empty, partial, stale, and error states distinct. Mobile cards stack without page-wide horizontal overflow, controls remain keyboard-operable, and signal meaning does not depend on color alone.

## Verification and non-goals

Use deterministic fixtures for source parsing, normalization, identity exclusion, liquidity and stale-date gates, score bounds/order, new-to-you grouping, cache/coalescing, safe partial failures, and absence of credentials or provider error bodies. Test the endpoint with fake provider responses and assert that no LLM or analysis job is called. Test Discover's rendered cards, 15/20 selection, refresh/empty states, saved-research badge, and Add to analysis behavior; inspect desktop and mobile layouts. Run the full Python and relevant JavaScript suites, Ruff, and diff checks. Do not make live provider calls as part of automated or manual QA unless the user explicitly initiates Refresh.

Non-goals: international exchanges, persistent personal watchlists, auto-trading, automatic full analysis, historical backtests, thematic LLM idea generation, and guaranteed delivery of exactly 15 or 20 names when the data does not qualify them.
